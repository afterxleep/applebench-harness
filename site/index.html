Can an AI agent fix a real Apple app?

AppleBench gives an AI coding agent a real Xcode project with a real bug. The agent must find the problem, fix it, and leave the project working.

AppleBench records every command and file change. After the agent stops, it builds the project from scratch, runs the tests, launches the app, and checks it on a simulator. {{ app_run_tasks }} of {{ scoring_tasks }} tasks cannot pass unless the app runs.

The agent never grades its own work.

Why another benchmark

Writing code is only part of the job.

understand → fix → build → run → test → verify

Many coding benchmarks stop after an agent edits some files. AppleBench checks what those edits actually produce. If the project does not build, the app crashes, or a required check fails, the task fails.

For each task, every model gets the same project, request, Xcode setup, simulator, and limits. The results show how many tasks it completed and what each run cost.

How a run is checked

The agent does the work. AppleBench checks the result.

Checks start after the agent stops

AppleBench uses a clean build and runs its own tests against the project the agent left behind. The agent saying “it works” does not count.

Every task is proven possible

Before a task is added, the broken project must fail and a known working fix must pass. All {{ scoring_tasks }} current tasks meet both rules.

No numbers are made up

Token counts and cost come from the agent tool. If it does not report them, they stay empty. Timeouts and final project results are recorded separately.

Scoring is simple

Every task starts at 10 points. A failed task gets 0. A passed task keeps all 10 points if it stays within 50,000 tokens; after that, its points fall as token use rises. How scoring works.

Scoring tasks stay private

The {{ scoring_tasks }} scoring tasks and their fixes are private. For published scores, the agent runs on a separate virtual Mac with no internet access, so it cannot look up the answers.

The harness is public. The answers are not.

Anyone can inspect and run the benchmark code.

The public repository includes the runner, the graders, and {{ sample_tasks }} sample tasks. The samples show exactly how a run works, but they never count toward a published score.

The {{ scoring_tasks }} scoring tasks and their reference fixes stay private. If the answers were online, a model could memorize or search for them, and the score would stop meaning much.

During a published scoring run, the agent works on a separate virtual Mac. It can use the project and Apple's developer tools, but it cannot use the internet. Every result records whether this protection was active.
