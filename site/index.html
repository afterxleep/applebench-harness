01 / The premise

Code is not the finished product.

  1. Understand
  2. Fix
  3. Build
  4. Run
  5. Test
  6. Verify

Many coding benchmarks stop at the diff. AppleBench keeps going. After the agent exits, the harness rebuilds the project from scratch, runs XCTest and XCUITest, resolves project settings, launches the app, and checks it on a simulator.

The agent never grades its own work.

03 / The standard

A pass has to survive inspection.

  1. Grade the workspace, not the transcript

    A clean build and independent tests run only after the agent stops.

  2. Prove every task is solvable

    The broken fixture must fail and its reference repair must pass before admission.

  3. Ask the device when the device matters

    {{ app_run_tasks }} tasks require the app to launch and behave correctly on a simulator.

  4. Publish the inconvenient numbers

    Failures, timeouts, tokens, cost, and grader evidence stay visible.

05 / Trust

The harness is public.
The answers are not.

Anyone can inspect the runner, graders, and {{ sample_tasks }} sample tasks. The {{ scoring_tasks }} scored tasks and their reference repairs remain private, and published runs execute on an isolated Mac without web access.

That keeps the benchmark inspectable without turning its answer key into training data.
